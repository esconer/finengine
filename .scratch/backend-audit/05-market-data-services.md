## Bugs

### P1 — wrong results

- [P1] `company_data_service.py:138` — `market_cap` changes units with the vendor tier: bfinance tier returns ₹ Crores, yfinance tier returns absolute ₹ — `"market_cap": r.market_cap or info.get("marketCap"),` — bfinance `Ratios.market_cap` is documented "Market Capitalization in ₹ Cr" (`bfinance/models/company.py:13`), while the yfinance tier maps raw `marketCap` (`company_data_service.py:67`, test fixture value `80000000000`/`1_900_000_000_000` in `test_coverage_alpha_vantage.py:230`, `test_data_services.py:123`). The same API field `/company/{ticker}/fundamentals` returns ~1000000× different magnitudes depending on the user's primary-source preference (`source_order_for`). `equity_research_service.py:85` correctly names the same bfinance value `market_cap_cr`, proving the unit. Fix: normalize to one unit at the tier boundary (emit `market_cap_cr` + `market_cap` absolute, or convert `r.market_cap * 1e7` before returning as `market_cap`). No test asserts unit consistency across tiers.
- [P1] `company_data_service.py:145` — `dividend_yield` unit flips with tier — `"dividend_yield": r.dividend_yield if r.dividend_yield is not None else info.get("dividendYield"),` — bfinance `Ratios.dividend_yield` is "Dividend Yield %" (`bfinance/models/company.py:19`, AI context prints `{r.dividend_yield:.2f}%`), yfinance `dividendYield` is a fraction (0.0085); this repo's own screener multiplies the yfinance-style key by 100 (`screener_service.py:295`). bfinance tier yields e.g. `0.85`, yfinance tier yields `0.0085` for the same field. Fix: convert one tier (e.g. `r.dividend_yield / 100.0`) so the contract is fraction everywhere, or split keys (`dividend_yield_pct`). Not covered by any test.
- [P1] `company_data_service.py:148` — `return_on_equity` unit flips with tier — `"return_on_equity": r.roe if r.roe is not None else info.get("returnOnEquity"),` — bfinance `Ratios.roe` is "ROCE/ROE %" (`bfinance/models/company.py:21`, mock `14.5` in `test_equity_research_and_screens.py:69`); yfinance `returnOnEquity` is a fraction (bfinance itself converts with `/ 100.0` to match yfinance at `bfinance/market/quotes.py:244`, and this repo's screener does `* 100` at `screener_service.py:292`). Bfinance tier → `14.5`, yfinance tier → `0.145`. Same fix as above; no unit-contract test exists.
- [P1] `alpha_vantage_service.py:263` — historical OHLCV request omits `outputsize`, so AV's default `compact` (~100 most recent sessions) silently truncates deep-history fetches — `data = await self._make_request("TIME_SERIES_DAILY", {"symbol": av_symbol})` — the caller `data_service._fetch_from_alpha_vantage` requests windows up to 10 years (`data_service.py:361` `_deep_start`); rows outside AV's compact window are simply absent, the non-empty partial frame is stored/served as a success (`data_service.py:798-813`). Tests mock `_make_request` with a pre-built series (`test_coverage_alpha_vantage.py:166`) so truncation is uncovered. Fix: `{"symbol": av_symbol, "outputsize": "full"}`.

### P2 — real bugs / broken contracts

- [P2] `equity_research_service.py:121` — every upstream failure is re-raised as `ValueError`, which the API maps to 404 — `raise ValueError(f"Failed to load research profile for {ticker}: {e}")` — `api/equity_research.py:46-47` converts `ValueError` → `404`, so a bfinance network outage is reported to the client as "ticker not found". Same pattern at `equity_research_service.py:186`, `:249`, `:283` (and `ai_dossier_service.py:50,70,86,102`, though AI routes catch generic `Exception` → 500). `company_data_service.py:107-108,177` already establishes the correct convention (RuntimeError → 503 for outages). Fix: only wrap genuine "not found" as ValueError; let transient errors surface as RuntimeError/503. Not tested.
- [P2] `screener_service.py:252` — vendor failure wrapped as `ValueError` → route returns 400 — `raise ValueError(f"Screen execution failed: {e}")` — `api/equity_research.py:205-206` maps ValueError → `400 Bad Request`, blaming the client for a bfinance outage. Inconsistent with the sibling custom-screen route which turns the same class of failure into 500 (`api/equity_research.py:227-229`). Fix: raise RuntimeError (503) for upstream failures, keep ValueError only for "Unknown strategy" (`screener_service.py:187`).
- [P2] `currency_service.py:188` — hardcoded FX fallback silently cached as a live rate — `rate = live_usd_inr if live_usd_inr and live_usd_inr > 0 else 83.0` — on any yfinance failure the constant `83.0` is stored under the normal cache key with `_last_updated` set (`:55-57`), so for 30 minutes `get_exchange_rate_info()['usd_to_inr']` (`:142`) reports `83.0` as if fetched, and `convert_amount` applies it to portfolio values. Tested only as intended behavior (`test_coverage_services_and_api.py:84-89`). Fix: don't cache the fallback (or mark the info payload `source=fallback`).
- [P2] `alpha_vantage_service.py:44-54` — `.BO` tickers are never bridged to AV's BSE suffix, contradicting the file's own mapping rationale — `if t.endswith(".NS"): return t[:-3] + ".BSE"` / docstring ":48 `.BO` already matches AV convention" — the same docstring (`:47-48`) states AV's BSE feed is `.BSE`, and `.BO` is yfinance's BSE suffix; so BSE-suffix holdings always fail the AV tier. Behavior locked in by `test_alpha_vantage.py:63`. Fix: also map `.BO` → `.BSE` (and update the test), or document that AV is skipped for `.BO`.
- [P2] `company_data_service.py:54-55` — `_to_thread` silently drops `*args` — `async def _to_thread(func, *args): return await asyncio.to_thread(func)` — any future caller passing arguments gets `func()` invoked with none (would raise TypeError or call with wrong arity). Sibling helpers forward correctly (`screener_service.py:55-56`, `equity_research_service.py:25-26`, `ai_dossier_service.py:22-23`). No current caller passes args (latent); no test covers it. Fix: `asyncio.to_thread(func, *args)`.
- [P2] `alpha_vantage_service.py:310` — quote response reports the bridged ticker, not the requested one — `"ticker": av_symbol.upper(),` — for `RELIANCE.NS` the quote dict says `RELIANCE.BSE`. The OHLCV path is re-normalized downstream (`data_service.py:884 df['ticker'] = ticker.upper()`), but `_fallback_quote` returns the AV dict unmodified (`data_service.py:825-841`), so quote API responses on the AV tier serve a different ticker than requested. Fix: return the original `ticker` argument (uppercased) in the dict.
- [P2] `equity_research_service.py:204-205` — `get_concalls` swallows all errors into an empty list — `logger.error(...); return []` — an upstream outage becomes HTTP 200 `{"count": 0}` (`api/equity_research.py:75-76`), indistinguishable from "company has no concalls". All sibling methods raise. Not tested for the error path. Fix: raise like `get_full_profile`.
- [P2] `equity_research_service.py:92` — same-field fallback mixes units inside one response — `"roe": r.roe if r.roe is not None else info.get("returnOnEquity"),` — `r.roe` is % (14.5) but `info.returnOnEquity` is the fraction bfinance derives via `r.roe / 100.0` (`bfinance/market/quotes.py:244`); when `r.roe` is None the field silently returns `0.145` where `14.5` is expected. Fixture models exactly this split (`test_equity_research_and_screens.py:42` `0.145` vs `:69` `14.5`). Fix: `info.get("returnOnEquity") * 100 if ... is not None else None`.
- [P2] `screener_service.py:295` — dividend-yield filter interprets the same bfinance quantity as a decimal while `equity_research_service.py:90` renders it as percent — `div_yield = (info.get("dividendYield") or 0.0) * 100` — bfinance sets `info["dividendYield"] = r.dividend_yield` raw (`bfinance/market/quotes.py:241`), the same value equity-research labels `%` (`:90`, bfinance AI context prints it with a `%` sign). If that value is percent (0.85), `*100` yields `85` and `min_div_yield=2.5` admits nearly every dividend payer; if it is a decimal, equity-research understates 100×. One of the two in-scope files is wrong (bfinance itself is contradictory: `screens.py:94-95` claims "decimals x100" while `quotes.py:241` does no conversion, unlike `:244` which does `/100`). Not covered: `test_p09_screener.py` custom-screen test never sets `min_div_yield`. Fix: pin the unit against bfinance, convert in one place.

- [P2] `company_data_service.py:167-177` — the yfinance fundamentals tier has no caching: every `GET /company/{ticker}/fundamentals` re-fetches `t.info` (with up to 3 rate-limit retries + sleeps at `:36-51`). bfinance's tier is covered by bfinance's built-in 24h SQLite cache (`bfinance/ticker.py:45` `SQLiteCache(default_ttl_hours=24)`), so the *fallback* tier is the one re-hitting the network on every request.
