## Defects the remediation itself introduced, and how they were caught

Worth recording, because the audit was adversarial by design:

- A duplicated `TICKER: TICKER:` prefix in warnings (fixed in the frontend
  first, then found again in the backend formatter).
- `regime` publishing holding dates contradicting the stored `added_on` for
  10/14 positions. Root cause: the buy-price inference was handed each route's
  own price window, so a wider lookback matched earlier buys and invented dates
  up to 11 months early. Now one pinned 252-day evidence window.
- `risk_contribution` laundering `buy_price_inferred` into `stored_added_on`,
  moving the window start a day and re-asserting the original defect.
- `liquidity.observation_window` structurally present but permanently null: the
  route kept the raw frame index, and a fresh yfinance fetch carries `date` as a
  column, so no delivered date could ever be read.
- A reconciliation field publishing `min(tolerances)` under the name
  `max_rounding_tolerance`, understating its own certified bound 139x.
- A transition-matrix docstring claiming Baum-Welch re-estimates the diagonal
  and that "persistence is in the data", when with the `mc` params setting it
  does not — the diagonal is a configured prior.

## Retracted

One audit finding (mojibake in warning text) was an artifact of the capture
pipeline, not the application: PowerShell's `Invoke-WebRequest` decodes UTF-8 as
Latin-1. The API emits a correct em dash. Capture now uses raw bytes.

## Known gaps, deliberately not closed

- Pairs' new `currency` / `warnings` reach the AI export but are stripped from
  the HTTP wire, because the route's `response_model` re-serializes against the
  base schema. Closing it is a one-line `schemas.py` promotion, left for a
  foundation-owned change rather than made unilaterally.
- The 30-day annualization gate still annualizes 36–39 observation samples
  (portfolio Tear Sheet reports a ~43% CAGR from a 39-day return). The window is
  now labelled and the measured days are published, but the GATE itself is
  unchanged; tightening it is a policy decision, not a bug fix.
