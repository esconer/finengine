## Ownership/coordination rules

1. A owns quant service files; B owns data/provider/cache/currency service files; C owns API files and `backend/main.py`; D owns models/schemas/config/db/migrations/deployment files.
2. No agent edits another owner's file. Cross-file needs are recorded as a patch recommendation in that owner's report and coordinated during integration.
3. Specifically: B owns currency/provider persistence; C may change API consumers but must not rewrite the currency service. C owns API config route; B owns source-preference helper. D owns schema constraints; C maps resulting integrity failures to 409. D owns migration/deployment/main foundation changes; C owns WebSocket/main API boundary and must avoid editing D-owned files without coordinator approval.
4. Every changed behavior receives a focused regression test or a deterministic evidence script, and every targeted command is recorded. No live network, real portfolio DB, dependency additions, commits, resets, checkouts, cleans, stashes, or history rewrites.
